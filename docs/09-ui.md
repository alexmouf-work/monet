# 09 — UI specification

Paint-3D-inspired: **feature tabs across the top, one contextual options panel on
the right**, canvas workspace in the middle, sources on the left. Clean, flat,
large hit targets. Light and dark themes (§9), both with a workspace surround
darker than the panels.

- `☰` = app menu (§2). `⚙` = settings dialog. `⤓` = export dialog. **Sync** [08 §7].
- **Toolbar row (owner directive 2026-08-09: "as few clicks away as possible").** An
  always-visible action bar of icon buttons in groups — File · History · Clipboard ·
  Canvas · View — then a spacer and the theme toggle right-aligned. Every button is
  also in the ☰ menu (which keeps the shortcut list for discovery), so the menu is
  never the *only* route to an action. Buttons disable when they cannot apply (no doc,
  no selection, empty history) and `aria-pressed` marks toggles (grid, tiling).
  Canvas rotate/flip in particular are here, not only in the Canvas tab.
- Doc tabs: dirty dot, close ×, middle-click closes, drag to reorder; `+` = new doc.
- Panels are fixed-width; workspace flexes. Minimum window 1100×640; below that
  the sources sidebar auto-collapses.

## 3. Feature tabs → options panel contents

The active tab decides both the **active tool family** and the right panel.
Switching tabs commits any pending state (open text edit, live preview → prompt
"Apply noise? Apply / Discard" if previewing with changes).

### 3.1 Brushes [02]
Tool grid (icon buttons): **Pixel pen · Marker · Eraser · Bucket** — the eyedropper
is in the colour panel (§5), not here — then the active brush's controls (size
slider+numeric 1–64, tip ◯/▢ toggle; bucket: tolerance 0–100 %). Footer note names
all three ways to pick a colour (💧, `I`, hold `Alt`).

### 3.2 Shapes [03]
Type grid with icons (triangle, rectangle, pentagon, hexagon, circle, ellipse,
arrow, arrowhead, line, spline) · Fill: ✔ + swatch + opacity slider · Outline:
✔ + swatch + opacity + weight 1–64 · Crisp edges ✔ · numeric X/Y/W/H ·
**Rotation 0–360°** slider+numeric · (spline hint: "click to add points — Enter
finishes, Esc cancels").

### 3.3 Text [03 §6]
Font dropdown (Monocraft default, bundled + generic; optional system-font
loader) · size 4–256 · **B I U** toggles · align ⟸ ⟺ ⟹ · colour + opacity ·
Rotation 0–360° · Crisp ✔.

### 3.4 Noise [04 §1] — type dropdown (grouped), rotation, scale, intensity,
Brightness/Hue checkboxes, seed + 🎲, **Apply** / **Reset**, objects-hint line.

### 3.5 Recolour [05 §1] — Replace | Opacity | Tint segmented control and the mode's
controls; in Replace a second segmented control, *Similar colours*: **Keep their differences** /
**Flatten to one** [05 §3.1]; in Opacity an **Opacity ×** 0–255 slider+box defaulting to
255 [05 §5]; **Recolour** button; objects-hint line.

### 3.5b Relight [05 §8] — Match | Adjust segmented control; Match carries the
from/to colour pickers with their brightness readouts and a before → after swatch,
the scale/curve/shift mapping choice and the optional colour limit; Adjust carries
brightness and contrast. Both carry the lightness/perceived measure toggle, Amount,
Preview and the **Relight** button.

### 3.6 Canvas [06 §1] — Background: Transparent|Colour + swatch · Resize…
(opens dialog) · Rotate ⟲ ⟳ · Flip ↔ ↕ · readout "32 × 32 px".

**Select** is a persistent tool button pinned left of the feature tabs (with Pan
next to it) — selection & moving are cross-cutting, not a tab.

## 8. Cursors & affordances

Brushes: `crosshair` + tip-outline overlay [02 §3.4] — the system cursor stays
**visible** on top of the outline (owner directive 2026-08-09: hiding it left
nothing to track at low zoom, where the outline is only a pixel or two across);
bucket/eyedropper: SVG
cursors with correct hot-spots (`cursor: url(...) x y, crosshair`); select:
default arrow, `move` inside selections/objects, rotate cursor near the rotation
handle, resize cursors matching each handle's angle (recompute for rotated
objects: pick from 8 directions by `handleAngle + rotation`); pan: `grab`/
`grabbing`; text: `text` over text objects.

Toasts (top-right, 4 s, dismissible): save/push results, sync results, errors.
Every icon button has a `title` tooltip incl. its shortcut.

## 9. Themes and palette

All chrome colours are CSS custom properties on `:root` (`src/ui/theme.css`) —
never literals in components. Three states, in this cascade order:

1. bare `:root` — the **light** palette (also the fallback if nothing else matches)
2. `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) { … } }`
3. `:root[data-theme='dark'] { … }` — an explicit choice must beat the media query

`data-theme` is stamped on `<html>` by `src/app/themeMode.ts`; the setting is
`system | light | dark`, cycled by the toolbar's theme button and persisted with
the rest of the settings. `system` removes the attribute rather than resolving it,
so the OS can change under a running tab (`watchSystemTheme`).

| Token | Light | Dark |
| ----- | ----- | ---- |
| `--surround` (workspace behind the canvas) | `#3d3d40` | `#15161a` |
| `--panel` / `--panel-2` | `#f5f6f8` / `#eceef2` | `#1e1f24` / `#272930` |
| `--border` | `#d9dce1` | `#383b43` |
| `--text` / `--text-dim` | `#1c1e21` / `#5b6270` | `#e7e8ec` / `#9aa1ab` |
| `--accent` / `--accent-soft` | `#3fa7d6` / `#e6f4fb` | `#4fb3e0` / `#16323f` |

Theme-independent, because they sit over document pixels rather than chrome:
checkerboard `#ffffff`/`#d4d4d4` · marching ants 1 px black over 1 px white
dashes · handles white fill, accent border, 8×8 px.

**The renderer cannot read CSS variables per frame.** `src/engine/themeColors.ts`
caches the ones it needs (`--surround`, `--accent`) from computed style;
`applyThemeMode` refreshes that cache and invalidates before the next frame.

## 11. Numeric fields

### 11.1 Empty while typing (owner report 2026-08-11)

**Every** numeric field in the app is `ui/controls/NumBox.tsx` — one implementation, so the
behaviour cannot drift between the brush size, a dialog and an object's W/H.

- A bare `<input type="number" value={n} onChange={+e.target.value}>` **cannot be emptied**:
  backspacing the last digit yields `''`, `+'' === 0` is committed, and the controlled value
  puts the digit straight back. NumBox keeps local text state instead — the box holds what you
  typed, including nothing at all — and commits only when the text parses.
- **Leaving it empty is resolved on blur (or Enter), not reverted**: the field takes its
  `emptyValue`, which is the brush size's **1** and an opacity's **255**. Default: `min`.
- A parseable value commits **live**, so previews and the paired slider follow as you type.
- The box follows the value when it changes for any other reason — a slider drag, `[`/`]`, a
  preset — but not when it already reads that number, so `007` is not rewritten under the caret
  and an empty box stays empty.
- `Slider` is a range input plus a NumBox and takes the same `emptyValue`. `NumField`
  (docs/11 §10.1) stays separate: it evaluates arithmetic and reverts on a bad parse, which is
  what model geometry wants.
